# Media Studio

An Android app for editing images and video — crop, filters, trim, upscale,
background removal, frame grabs — plus **prompt-based editing**: describe the
change in words and the image or clip is regenerated by an AI model.

Two parts, deployable as-is:

| Part | Stack | What it does |
|---|---|---|
| `backend/` | FastAPI + Pillow + ffmpeg | All media work. Deterministic edits run locally; AI edits go through a pluggable provider. |
| `android/` | Kotlin + Jetpack Compose | The app: pick media, tweak sliders, type a prompt, see the result. |

The AI layer ships with four providers behind one interface — **fal.ai**,
**Google Gemini**, **Replicate**, and a **mock** provider that works offline.
You add a key, set one env var, and real models are live. No Android rebuild
needed.

## v2: what this build adds

**Prompt studio — footage in, finished video out.** Paste a description like your
rental-property prompt, add clips, and the backend analyses the footage (shot
boundaries, sharpness, duplicates, silence), builds an edit decision list with
titles bound to shots, and returns the plan for review. Only after you approve
it does anything render. `POST /v1/auto/plan` then `POST /v1/auto/render`.

**Very large files.** Uploads no longer load into memory. `POST /v1/uploads`
opens a session, `PUT /v1/uploads/{id}?offset=N` appends chunks streamed
straight to disk, `GET` reports the received offset so a dropped connection
resumes instead of restarting, and `POST /v1/uploads/{id}/complete` registers
the asset and builds a 540p proxy for scrubbing. Limit is 20 GB by default
(`MAX_UPLOAD_GB`), with 16 MB chunks (`CHUNK_SIZE_MB`).

**Feature coverage you can check.** All 245 functions from the specification are
registered in `backend/app/features.py` with a real status, exposed at
`GET /v1/features` and `/v1/features/summary`, and reported by `/health`.
Seventy-one are implemented in this build; the rest are marked planned rather
than quietly implied.

```bash
curl -s localhost:8000/v1/features/summary | jq
# {"total": 245, "implemented": 71, "planned": 174, "modules": [...]}
```

**New tests.** `scripts/smoke_v2.py` generates footage, pushes it through the
chunked-upload path, asks the planner for a plan, renders it, and probes the
output — 21 checks, no API key required.

```bash
cd backend && .venv/bin/python scripts/smoke_v2.py
```

Two honest notes on the renderer: cross-dissolve needs an ffmpeg build with a
compatible encoder configuration, so the join falls back to a fade-to-black cut
and records that in the render report rather than failing; and background music
still has to be a file you supply or license — the pipeline muxes and
loudness-normalises it, it does not invent music.

## What it can do

**Images**
- Crop, rotate, flip, resize (`cover`/`contain`/`stretch`)
- Brightness, contrast, saturation, sharpness, blur
- Filter presets: grayscale, sepia, warm, cool, vintage, punch, mono
- Prompt edit — "make it a rainy night in Mumbai, neon reflections"
- Text-to-image generation from scratch
- 2× upscale
- Background removal → transparent PNG

**Video**
- Trim with frame accuracy (or instant keyframe-snapping stream copy)
- Merge clips
- Grab a still frame (which then opens in the image editor)
- Prompt restyle (video-to-video)
- Text-to-video generation

Every operation returns a **new** asset with its own id — the original is never
overwritten, so undo is free and provenance (`tool`, `prompt`, `provider`) is
recorded on each result.

## Quickstart (backend)

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
sudo apt-get install ffmpeg          # macOS: brew install ffmpeg
cp .env.example .env                 # defaults to AI_PROVIDER=mock
.venv/bin/uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Open http://localhost:8000/docs for the interactive API.

Verify everything end to end (works with no API key — uses the mock provider):

```bash
.venv/bin/python scripts/smoke_test.py
```

```
PASS  upload image
PASS  adjust image
PASS  prompt edit job succeeded
PASS  text-to-image job
PASS  upload video
PASS  trim video
PASS  text-to-video job
All checks passed.
```

Or with Docker: `docker compose up --build` (ffmpeg is baked into the image).

## Quickstart (Android)

1. Open the `android/` folder in Android Studio (Ladybug or newer).
2. Let Gradle sync — it generates the wrapper if your IDE asks.
3. Set the backend URL in `android/gradle.properties`:
   ```properties
   # emulator -> your machine
   MEDIA_API_BASE_URL=http://10.0.2.2:8000/
   # physical phone on the same Wi-Fi -> use your machine's LAN IP
   # MEDIA_API_BASE_URL=http://192.168.1.42:8000/
   ```
4. Run on a device/emulator with API 24+.

Pick an image or video, or type a prompt and hit *Generate image* / *Generate
video*. Progress shows as an overlay while the job runs; **Undo** steps back
through results.

> Cleartext HTTP is allowed only for `10.0.2.2`, `localhost` and `192.168.*`
> (see `res/xml/network_security_config.xml`). Point the app at an HTTPS URL in
> production and you can delete that file.

## Turning on real AI

Pick a provider, add the key to `backend/.env`, restart.

### fal.ai — recommended
One key covers every capability in the app: image editing (FLUX Kontext),
text-to-image, upscaling, background removal, text-to-video and video-to-video.

```env
AI_PROVIDER=fal
FAL_KEY=your-key
```

Model ids live in `.env` so you can swap them without touching code:
`IMAGE_EDIT_MODEL`, `IMAGE_GEN_MODEL`, `UPSCALE_MODEL`, `BG_REMOVAL_MODEL`,
`VIDEO_GEN_MODEL`, `VIDEO_EDIT_MODEL`. Check fal's model catalogue for current
names — providers rename and version models regularly.

### Google Gemini — cheapest for image editing
Good instruction-following for image edits. **Images only** — video endpoints
will return a clear "not supported by the configured provider" job error.

```env
AI_PROVIDER=gemini
GEMINI_API_KEY=your-key
```

### Replicate — any hosted model
```env
AI_PROVIDER=replicate
REPLICATE_API_TOKEN=your-token
REPLICATE_IMAGE_EDIT_MODEL=black-forest-labs/flux-kontext-pro
```

### Mock — no key, no cost
`AI_PROVIDER=mock` (the default). It stamps your prompt on the image and grades
it by a hash, and renders a placeholder clip with ffmpeg. Visibly fake on
purpose, so you can build and test the whole pipeline before spending on
credits. **Never ship this to real users.**

### Cost and rate limits, honestly
AI calls bill per request and video generation is the expensive one — a single
clip typically costs an order of magnitude more than an image edit, and both
vary by model and resolution. Before you launch: check the provider's current
price list, cap clip length and resolution in the app, and put an API-key
dependency plus per-user quota on the routers (`docs/ARCHITECTURE.md` → Scaling).
The deterministic tools (crop, filters, trim, frame grab) cost nothing and run
on your own server — keep the free/paid split visible in the UI.

| `POST /v1/videos/merge` | `Job` | concat clips |
| `POST /v1/videos/generate` | `Job` | text-to-video |

| `POST /v1/uploads` | `UploadSessionOut` | start a resumable upload |

## Deploying

```bash
cd backend
docker build -t media-studio-api .
docker run -p 8000:8000 --env-file .env -v media:/data media-studio-api
```

Works unchanged on Cloud Run, Render, Railway or Fly.io — it is a single
container with ffmpeg. Set `PUBLIC_BASE_URL` to the public HTTPS URL so media
links in the app resolve, and mount a persistent volume at `/data` (or switch
`MediaStore` to S3/R2).

## Known limits

- Jobs are in-process: one replica only until you move the job store to Redis.
- No auth or rate limiting yet — add it before going public.
- Uploads are read fully into memory; fine to ~200 MB, stream them for more.
- HEIC from iOS cameras is accepted by extension but Pillow needs
  `pillow-heif` to decode it — add that package if you expect iPhone uploads.
- The mock provider is a development stub, not a real model.
